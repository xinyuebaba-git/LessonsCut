# ChatCut 适配经验（可选）

仅在用户选择 ChatCut 或继续已有时间线任务时使用。服务器独立剪辑应用不依赖 ChatCut 浏览器、OAuth 或 Hosted MCP。

## 工具调用顺序

1. 读取当前安装的 ChatCut 基础技能，发现 Hosted MCP 工具；不要混用 Desktop 接口。调用 `get_active_project`，核实项目、时间线、素材、fps、轨道与字幕，再写入。
2. 备份时间线并保存结构快照。用 `import_media` 导入原素材/生成页，按当前 schema 修改或添加项目；`assetId` 更新不可变时采用已备份的删除再添加，不强行 relink。
3. 需要保留旧标题音轨时，可将旧标题视频缩短到目标长度、上层用完整不透明新标题图覆盖。必须检查上下层范围、可见性、边缘和音频；不能仅用局部遮罩覆盖制作单位。
4. 用 `preview_timeline` 检查实际渲染的首/中/末标题帧、衔接帧与必要字幕帧。大跨度预览曾超时，可改为相邻 3–4 帧小范围请求；不能因超时省略验证。
5. 对明确指定项目与时间线调用 `submit_export`，再 `track_export` 按返回的 checkBackAfterSeconds 查询。历史成功参数为 `resolution=1080p, format=video, codec=h264, fps=30, renderMode=local`；30fps 是当时项目值，不能用于所有素材。
6. 本地浏览器导出保持标签页打开。完成状态不含可下载文件时，在对应新任务条目点击“再次下载”，监听下载事件得到实际路径。不要误取同队列旧成片，也不要广泛扫描不相关下载文件。
7. 对实际 MP4 执行完整验收，另存到用户指定目录并核对哈希，保留可编辑时间线。

工具参数必须按当前实际声明检查；本文是经验证的适配经验，不保证未来版本 schema 不变。

## 字幕修订陷阱

3 号标题缩短 5 帧后，169 张卡中的 11 张手工卡保留了旧绝对 token 时间，自动卡已跟随素材移动。单纯刷新不修复；set_card_tokens 还可能因时间超出当前卡边界而失败。

遇到同类问题：备份全部文本、token 时间和样式；在临时副本验证，仅对受影响的手工卡按最新 revision 执行 reset_card，再读取正确的自动卡，以原修订文本 set_card_text，最后逐字比较原时间减统一偏移量。若 API 当前行为不一致，停止套用此方法并诊断。

不得重置全部字幕或丢弃手工校正文案；不能把字幕重置当成通用必要步骤。修复后全量检查文字及时间，实际渲染抽样检查高亮，删除仅为诊断创建且已无用的副本，保留用户备份。
