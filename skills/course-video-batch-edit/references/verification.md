# 检查与验收

## 证据链

通过结论必须指向相同 source_hash、plan_revision、render_hash 和 review_revision。计划通过不能代替渲染通过；编辑器预览不能代替实际 MP4；工具 status=complete 不能代替文件存在、可解码与内容正确。

按检查项记录 `pass | fail | uncertain | not_applicable`。必需项为 fail 或 uncertain 就不能自动交付。人工例外保留原结论、理由和操作者，报告明确“人工接受例外”，不能修改成模型通过。

## 计划检查

- 源素材与批准片头资产存在且哈希一致，生成页与批准文本绑定。
- 视频主序列无空洞、重复或意外重叠；片头→标题→连续授课。
- 片头时长、标题帧数和输出实际时长符合模板量化规则；授课 source range 单一连续（内部可拆轨，但映射相邻）。
- 切点具有邻帧证据和必要语音上下文，保留全部有效授课；源/输出音频映射与视频映射一致。
- 修订改变任何时间时，检查全部依赖的字幕/叠加项。首版应用不新增字幕；既有外部可编辑字幕工程需要兼容适配或转人工，不扁平覆盖后宣称仍可编辑。

## 实际输出机械检查

1. ffprobe 读取分辨率、编码、声道、采样率、帧率、流起始时间、帧数和容器/流时长。缺少 nb_frames 时完整解码计数，不能把 null 当零。
2. 完整解码所有交付视频和音频流，错误即失败；按规范化计划检查帧数与逐段时长。默认允许流时长与标称帧时长相差至多一帧加 1ms，超出转诊断；编码器实际样本时长规则需在配置记录。
3. 音频在授课首、中、尾选三段有效非静音样本（各最多 8 秒，短片缩短并避免重叠），按 source→output 映射计算相关性和延迟。默认筛查阈值：相关系数 ≥0.90，绝对残余延迟 ≤80ms，首尾延迟变化 ≤40ms；阈值为首版待标定工程门槛，不是普适听感保证。已知 encoder delay / priming 单独记录后计算残余偏移。
4. 持续静音、周期性配乐或低相关导致无法可靠对齐时标 uncertain，不得据相关性判定语义完整。尾部 padding 默认上限 120ms，单独记录，不能借 padding 容忍度放过授课中间漂移。
5. 检查源哈希未变；若音频重新编码只说明声音内容保留，不称载荷一致。确实使用音频 copy 才可另外比对压缩载荷。

以上完整解码与三点音频检查是应用验收要求；历史 1/3 号仅做过单段音频相关性检查，不能把新要求倒填成旧结果。

## 实际输出模型检查

必查片头代表帧与末帧、标题首/中/末帧、授课起点前后、结尾前后。对应源帧与输出帧成对比较，依据 PTS 映射，不默认用固定 frame offset。

授课默认每 30 秒抽样，另加每个已发现转场、字幕或标题疑点前后样本。明确保存抽样清单与覆盖率；静态图片可以核查内容、文字、裁切，不能证明动态无闪烁、语音衔接或全片视觉完整。云端本轮只允许报告、必要帧与文字证据；需要音视频片段才能定论的事项转人工，不擅自上传整片。

生成页只允许批准课名和讲师文本，检查风格、错字、残留系列/制作信息、字被裁切。授课画面允许保留原本出现的文字，不能把讲课 PPT 中的单位名称误判为“标题页残留”。

## 发布与报告

发布前再次确认审核文件哈希；在目标文件系统中以新临时文件复制/写入、校验、fsync，再使用无替换的原子发布机制。文件名冲突生成新后缀，不能先检查 exists 再使用可覆盖 rename。目标只在所有必需项通过或人工明确接受例外后出现为可下载成片。

报告必须包括源与输出标识、课名及姓名来源、切点与实际时长、所用模型版本、生成页版本、机械结果、样本清单与模型结论、限制/例外、用量和未知调用数。临时失败产物保留以供排查，不作为交付文件展示。

## 已批准的收束语定格

计划分别记录视觉终点与原声终点。机械检查定格时长向上量化为整帧，抽取最后运动帧与定格首中末帧比较；对延长后的原声范围执行首中尾对齐。另从实际MP4末尾截取音频交本地ASR重新识别，由指定本地识别模型和云端监督分别核对完整收束、未带预告及最后授课帧一致。云端只读转写和抽帧，不声称听审；任一必需项无法确认则不发布。
