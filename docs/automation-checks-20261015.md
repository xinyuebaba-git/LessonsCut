## 本轮发现并处理的问题

- 纯“主讲姓名”署名卡可能被当真人；增加实际真人出镜核验。片头卡通演示增加顺序/转写上下文核验。
- 结尾学校品牌卡可能与片头外观相同；按最终教学之后的时序提出片尾候选，再精查，不靠单帧品牌类别截断。
- 云端一次接收较多图片时出现帧号和文字混用；拆分为独立课名、姓名、起点、终点及事实核对。每图附文件名标识，不用本地通过结论引导独立读取。
- 原片PPT不能取代开场标题的视觉风格；标题样式从开场实际标题候选选择。
- 1号生图初稿/修订夹带系列文字，实际标题复核拦截；初稿加两轮修正范围内最终通过。所有原响应与usage保留，未将前两次失败删除。
- 模型格式错误最多两次格式修复；不把格式修复用于消除真实语义分歧。未知执行状态不自动重复付费调用。
- 精确源PTS抽帧及整数源帧trim，保持连续授课；渲染检查点绑定计划/标题哈希。人工新修订清除旧计划通过结论和旧成片校验，保留源证据。

## 本地ASR与资源

本轮在服务器隔离venv安装faster-whisper 1.2.1及固定哈希large-v3-turbo权重，CPU/int8、16线程，认证SSH传音频，无新公开端口。实际检查3090为24576MiB，Qwen占用约20810MiB；CPU转写没有加载第二个GPU模型。

两条素材均完成全片本地词级转写。开发过程中3号曾在锁保护代码生效前重复执行一次，全量记录保留：3次本地ASR共1481.386625音频秒；这是处理工作量，不能当独立素材总时长或token。后续同任务同修订ASR以文件锁与源/音频/配置哈希缓存避免重复运行。
