# 验收案例集 v1.0

本文件是后续实现的验收规格。`H` 为已保存的历史结果，`A` 为待运行的应用验收用例；写出预期不等于测试已通过。本次仅完成 [文档与证据检查](validation-report.md)。

## 历史基线

[historical-baseline.json](examples/historical-baseline.json) 包含已读取证据的源/输出哈希、帧范围、标题、实际规格、usage 和样本音频检查。路径相对项目根目录；源视频位于用户原视频目录，默认不复制到技能包。迁移测试必须按 hash 绑定素材，而不是只匹配文件名。

| 编号 | 输入/历史行为 | 基线与限制 |
|---|---|---|
| H01 | 1.mp4 标题含非课名信息，按本节课口头说明确定课名 | 名誉侵权；符敏妍；6s＋45帧标题；授课源 [803,11322)，输出10744帧；实际MP4样本通过 |
| H03 | 3.mp4 从授课页面取课名；生图首版风格失败 | 农村电商园区经验分享；姚雅晴；使用v2生成图；授课源 [653,16227)，输出15799帧 |
| H03-C | 已有 ChatCut 动态字幕工程，标题缩短5帧 | 169张卡文字保留，11张手工卡逐字时间前移5帧；只用于ChatCut兼容扩展 |
| H-EXPORT | 两文件浏览器导出完整解码和Qwen抽样 | 输出1920×1080、30fps、H.264/AAC；源哈希不变；4次调用16,310 tokens，usage无缺失 |

迁移复测只比较课程内容范围、标题、时长/帧数等业务不变量；新编码器输出 hash 不应等于历史 MP4 hash。3号首版基础应用不新增历史动态字幕，因此不能要求全片像素与历史成片一致。历史人工批准的标题可作为基线输入，不能证明新模型会自动识别出相同标题。

## GPU 压测与应用发布门槛

目标服务器上先使用实际模型与8秒媒体片段做健康/能力测试，再以1、3号和长课程组合跑批。依次测识别单任务、渲染单任务、本地生图切换和候选并发，记录吞吐、耗时分位数、显存峰值、CPU/内存、OOM和返工率。并发默认关闭，只有稳定重复试运行且质量不下降才启用共存。

首次真实云端测试前绑定预算和外发策略，保留每次实际发送清单。对未知费用的请求用调用数和耗时限制兜底；额度不足不能静默换模型。UI必须正确显示等待GPU、待人工和使用量未知。

发布要求：A01–A32逐项有实际记录（不适用必须说明适配范围），硬性不覆盖/解码/哈希/时间映射项全部通过；模型意见冲突不得自动发布；关键阶段重启与恢复验证通过；所有真实外部调用有记录或明确未知usage。完成这些之前只能称设计或试运行，不能称生产验收通过。

ChatCut扩展单独回放H03-C：备份→临时副本→局部重绑→169张卡全量检查→真实帧高亮复核。首版独立应用验收不要求实现该扩展。
